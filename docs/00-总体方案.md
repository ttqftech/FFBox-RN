# FFa0x 总体实现方案

> FFa0x 是 FFBox 的移动端（React Native / Expo）复刻项目。本方案遵循「**分步实现，每步可运行**」的原则，从最小可用功能开始逐步完善。未实现的入口一律保留 TODO 或 UI 提示，避免点击后崩溃。

---

## 1. 项目定位与范围

- **本质**：一个**远程 FFBox 服务端的管理客户端**。它不内嵌转码引擎，而是通过 FFBox 服务端暴露的 HTTP REST + WebSocket 接口，实现登录、任务管理、参数配置、文件上传下载等能力。
- **技术栈**：React Native + Expo SDK 57 + expo-router（项目已初始化，见 `src/app`）。
- **与 FFBox 的关系**：界面相关核心类型尽量与 FFBox 保持一致（`appStore`、`UITask`、`Run`、`OutputParams` 等），但数据更新方式由 Vue 响应式改为 RN 端的响应式状态库。

---

## 2. FFBox 服务端通信原理解析（必须理解）

FFBox 前端通过 `src/renderer/src/bridges/serviceBridge.ts` 与后端通信，核心是**三层**：

1. **HTTP 探测 + 登录**：
   - `GET /api/v1/system/version` 探测版本。
   - `POST /api/v1/auth/login`（body: `{ username, passkey: SHA256(password) }`）换取 `sessionId` 与 `permissions`。
2. **WebSocket 长连接**：`ws://{ip}:{port}/?sessionId=...`
   - 客户端发 `{ type: 'subscribe' | 'replaceSubscription', taskIds }` 订阅任务。
   - 服务端推送事件，见下。
3. **HTTP 业务接口**：任务增删改、参数设置、上传下载等都走 `httpRequest`，带 `Authorization: Bearer {sessionId}`。

### 2.1 WebSocket 事件（`FFBoxServiceEventParam`）

| 事件 | 载荷 | 用途 |
|---|---|---|
| `ffmpegInfo` | `FFmpegInfo` | 编码器/复用器扫描信息 |
| `workingStatusUpdate` | `{ workingStatus?, progress }` | 队列启停 + 总进度 |
| `tasklistUpdate` | `{ added?, removed?, totalCount }` | 任务列表增删 |
| `taskUpdate` | `{ taskId, task }` | 任务整体更新（剥离 progressLog/cmdData） |
| `cmdUpdate` | `{ taskId, runIndex, content, append }` | 命令行/日志增量 |
| `progressUpdate` | `{ taskId, runIndex, time, status }` | 进度增量 |
| `notificationUpdate` | `{ notificationId, notification? }` | 通知 |
| `asyncListUpdate` | `{ list }` | 异步操作列表 |

### 2.2 关键 HTTP 接口（`serviceBridge.ts` 已封装）

```ts
taskAddBatch(filePaths, outputParams?) -> number[]      // POST /api/v1/tasks
taskDelete(ids)                                          // POST /api/v1/tasks/delete
taskStart / taskReady / taskPause / taskResume / taskReset
queueStart / queuePause                                  // POST /api/v1/queue/start|pause
setParameters(ids, params, fullyReplace)                 // PUT /api/v1/tasks/parameters
getTaskList(offset, size) -> { tasks, totalCount }
getTaskIdsByStatus(status) -> { taskIds }
getTask(taskId) -> Task
getOutputFiles(entries) -> [...]
mergeUploaded(id, hashs, fileBaseName, inputName, ...)   // 上传合并
setUploadStatus(id, isUploading)
getAVOptions() -> codecs/formats/filters                 // GET /api/v1/system/codecs
getProperties / getWorkingStatus / getNotifications / activate
```

> **迁移结论**：RN 的 `fetch` 与内置 `WebSocket` 与浏览器几乎一致，`serviceBridge.ts` 可以**近乎原样移植**，仅需把 `EventEmitter` 换成 RN 可用的事件实现（用 npm 的 `events` 包，见步骤 2）。

## 3. 技术选型总览

| 关注点 | 选用库 | 理由 | 可替代方案 |
|---|---|---|---|
| 导航 | `expo-router`（已装） | 文件路由，官方推荐，与原生栈体验一致 | `react-navigation` |
| 响应式状态 | **`valtio`** | Proxy 响应式，写法最接近 Vue/Pinia，符合「禁 redux」要求 | `zustand`, `mobx` |
| 本地存储 | `@react-native-async-storage/async-storage` | 存「最近使用服务器」「预设」 | `expo-sqlite` |
| 事件总线 | `events`（npm 自带 polyfill，已在 package.json） | ServiceBridge 继承 EventEmitter，纯 JS 明文可用 | `mitt`, `eventemitter3` |
| 手势 | `react-native-gesture-handler`（已装）+ `react-native-reanimated`（已装） | 任务条左滑露出操作按钮 | 纯 RN `PanResponder` |
| 文件选择 | `expo-document-picker`（通用）+ `expo-image-picker`（相册/媒体） | 支持任意类型；相册优先 | `react-native-image-picker` |
| 上传 | `react-native-blob-util` | 分片上传 + 进度回调 + 后台 | 原生 `fetch`+`FormData`（无进度） |
| 下载 | `expo-file-system` | 后台下载、断点、本地存储 | `fetch`+写文件 |
| 哈希 | `expo-crypto`（SHA256=SHA1 登录/上传校验） | 官方、原生实现快 | `crypto-js` |
| 图标 | `@expo/vector-icons` / `expo-symbols`（已装） | 状态图标/按钮图标 | 本地 SVG |
| Swipe 标签 | `react-native-pager-view`（视频/音频/封装/输入） | 原生横向滑动切换 | 自绘 ScrollView 分段 |

> **详细选型示例代码、理由、替代方案见各步骤文档**。总体原则：**避免过度抽象**，能用一个官方/轻量库解决就不引入重型框架。

## 4. 数据模型（对齐 FFBox）

`src/renderer/src/types.ts` 的核心类型，RN 侧基本照搬：

```ts
export interface ServerData {
  id: string;
  name: string;
  tasks: UITask[];
  taskIdToIndex: Map<number, number>;
  notifications: Notification[];
  uploadFiles: UploadFile[];
  downloadFiles: DownloadFile[];
  ffmpegInfo: FFmpegInfo;
  version?: string;
  totalCount: number;
  workingStatus: WorkingStatus;
  progress: number;          // -1 或 0~1
  asyncList: { type: string }[];
}
export interface Server { data: ServerData; entity: ServiceBridge; }

export interface UIRun extends Run {
  dashboard: {...}; dashboard_smooth: {...};
}
export interface UITask extends Omit<Task,'runs'> {
  taskIndex: number;
  selectedRunIndex: number;
  runs: UIRun[];
}
```

> FFBox 的 `Run`、`Task`、`OutputParams`、`TaskStatus` 等定义在 `@common/types`，可按需复制到 `src/types.ts`（或从 FFBox 拷贝编译）。

## 7. 关键设计决策（与描述对齐）

1. **单服务器**：`appStore.servers` 固定只含一个元素（预留多服务器数据结构，但界面只连一个）。
2. **多选模式**：`selectedTask: Set<number>`，`undefined` 表示非选择模式；按钮在「多选」与「反选」之间切换；反选后数量为 0 则退出选择模式。
3. **任务条交互**：left-swipe 露出操作按钮（选择预设 + 暂停/重置/删除）；非选择模式点击进详情。
4. **参数编辑「保存才生效」**：编辑页修改参数仅改本地草稿，点保存写入预设，**不**影响现有任务（与 FFBox 的即时 apply 不同）。
5. **掉线**：任务列表隐藏，居中显示「掉线 + 重试」；复活时自动重连 1 次。自动重连标记放在 ServiceBridge 实体层（`reconnectAttempted` 字段），用户手动断开时不自动重连，仅意外掉线才自动重连 1 次。
6. **后台监听**：WebSocket 常驻，store 任何时刻同步（遵守系统默认后台策略，不做手动保活）；仅 UI 更新依赖页面挂载。
7. **上传/下载**：作为后台逻辑模块，不依赖页面存活。

## 8. 未实现功能的规避策略

- 每个页面/按钮在未实现时给出占位 UI（灰态 + 「尚未实现」提示）。
- 所有调后端接口的入口挂在 `appStore` action 上；未接通时 action 内 `return` 并弹提示，避免崩溃。
- 引入通用 `Toast`/`Confirm` 组件，替代 FFBox 的 `Popup`/`Msgbox`/`showMenu`。

## 9. 风险与注意事项

- **`getFFmpegParaArray` 体积大**：步骤 5 需要移植，但只移植 FFa0x 用到的子集（无需滤镜图、多输出等），其余留 TODO。
- **上传在 RN 的差异**：`blob.arrayBuffer()` 在 RN 受限，改用 `react-native-blob-util` 的 `readFile('base64')` 或 `slice` 处理分片；Web Worker 不可用，哈希改为 `expo-crypto` 同步逐片计算。
- **下载保存**：需 `expo-file-system` 写文件 + `expo-media-library` 申请权限并保存到相册/存储。
- **网络权限**（Android）：`app.json` 需配置 `usesCleartextTraffic`（FFBox 服务端常为 http），并申请存储/媒体权限。
