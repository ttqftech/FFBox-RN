## 4.2 库选型

### 4.2.1 文件选择

**`expo-image-picker`（相册/媒体优先）** + **`expo-document-picker`（所有文件）**

**理由**：需求明确「优先按相册形式选择媒体文件，同时支持所有文件的选择」。image-picker 提供相册媒体，document-picker 提供任意类型文件。

```bash
pnpm exec expo install expo-image-picker expo-document-picker
```

```ts
// 相册/媒体
import * as ImagePicker from 'expo-image-picker';
const res = await ImagePicker.launchImageLibraryAsync({ mediaTypes: ['images', 'videos'], allowsMultipleSelection: true });

// 所有文件
import * as DocumentPicker from 'expo-document-picker';
const res = await DocumentPicker.getDocumentAsync({ multiple: true, copyToCacheDirectory: true });
```

**替代方案**：`react-native-image-picker`（仅媒体，不含任意文件）。

> 实现上：先给「相册选择」入口，再给「文件选择」入口；或用一个动作弹菜单二选一。

### 4.2.2 文件读取：`expo-file-system/legacy` 按偏移读取（**仅此用途**）

~~原计划 `react-native-blob-util`~~（实现时验证发现其 `readFile(uri, 'base64', offset, len)` 并不支持 offset/len 参数），改用 `expo-file-system/legacy` 的 `readAsStringAsync`（支持 `position` + `length` 按偏移切片读 base64，替代 FFBox 的 `nodeBridge.getLocalFileChunk(input, offset, size)`）。

```bash
pnpm exec expo install expo-file-system base64-js
```

```ts
import { getInfoAsync, readAsStringAsync } from 'expo-file-system/legacy';

// 读文件大小
const info = await getInfoAsync(fileUri);
const fileSize = info.exists ? info.size : 0;

// 读指定偏移、指定长度的分片（返回 base64）
const base64 = await readAsStringAsync(fileUri, { encoding: 'base64', position: offset, length: chunkSize });
```

> 分片 base64 → 原始字节用 `base64-js` 的 `toByteArray`（见 4.2.3）。

> **内存注意**：base64 是 JS 字符串，占内存约为原始字节的 4/3。继续沿用 FFBox 的 `memLimit`（≥100MB 哈希后即释放不缓存），分片保持 `<1GB → 4MB / ≥1GB → 20MB`。

### 4.2.3 分片上传：RN 原生 `XMLHttpRequest`（照搬 FFBox）

fetch 无法在上传时反馈进度，但 **FFBox 上传分片本来就用的 `XMLHttpRequest` + `xhr.upload.onprogress`**（见 `transferManager2.ts`），而 RN 的 XHR polyfill **同样支持上传进度事件**（native 侧 `didSendNetworkData` → 转发到 `xhr.upload` 的 `progress`）。因此这一段**直接照搬 FFBox 实现，无需任何上传库**。

```ts
const xhr = new XMLHttpRequest();
xhr.upload.addEventListener('progress', (e => chunk.transferred = e.loaded), false);
xhr.onreadystatechange = () => { /* 4xx/5xx 判定，同 FFBox */ };
xhr.onload = () => { chunk.status = 'finished'; chunk.transferred = chunk.size; resolve(0); };
xhr.onabort = () => { /* paused，同 FFBox */ };
xhr.open('post', `${url}/api/v1/upload/file/`, true);
xhr.setRequestHeader('Authorization', `Bearer ${sessionId}`);
xhr.send(form);
```

> **上传前把 base64 还原成原始字节**再挂 FormData（与 FFBox 的 `new Blob([chunk.buffer])` 语义一致）：
> `form.append('name', chunkHash); form.append('file', new Blob([base64ToBytes(base64)]), chunkHash);`
> 其中 `base64ToBytes` 用 `base64-js` 的 `toByteArray`。

**替代方案**：blob-util 的 `fetch` + `uploadProgress`（也可行，但 FFBox 已是 XHR，照搬复用度更高）；`expo-file-system` 的 `uploadAsync`（multipart/并发控制弱）。

### 4.2.4 分片哈希：原生哈希，**不**复刻 Web Worker

RN（Hermes）**没有 Web Worker**；`react-native-worklets`（重动画）跑在 UI 线程且限制多，不适合哈希。加速哈希的正解是走**原生层**——

**首选（零新依赖，已装 `expo-crypto`）**：`digestStringAsync` 是异步原生模块，digest 在原生后台线程算、不卡 JS 线程；配合保留的 `SingleTaskScheduler`（并发>1），多个 await 并发挂起即可完成哈希。

```ts
import * as Crypto from 'expo-crypto';
const hash = await Crypto.digestStringAsync(Crypto.CryptoDigestAlgorithm.SHA1, base64);
```

> **代价**：它只哈希字符串。喂 base64 得到的是「base64 串的 SHA1」，与 FFBox 的「原始字节 SHA1」不一致，仅影响**同一文件在 FFBox 桌面端 / FFa0x 手机端之间互相秒传/去重**（服务端按 hash 存块）；对协议与 `mergeUploaded` 无影响。

**保真备选**：`react-native-quick-crypto` → `createHash('sha1').update(Buffer.from(base64,'base64')).digest('hex')`，纯原生 C++、算原始字节，语义与 FFBox 一致；代价是需 dev build。

**由此简化**：可整段删掉 FFBox 的 `hashWorkers` / `hashWorkerRunningList` / `ensureHashWorkerList` / `terminateAllHashWorkers` 及 ts2 的「挑空闲 worker + postMessage」逻辑；并发调度器 `SingleTaskScheduler` 与服务端调用原样保留。

> 若日后要真·多核原生并行：写一个小型 Expo Module（Swift GCD / Kotlin Dispatchers.IO）按 chunk 并发哈希。当前属过度设计，暂不实现。

### 4.2.5 后台模块组织

上传/下载不依赖页面，抽象成 `transferManager.ts`（参考 `transferManager2.ts` 的 `SingleTaskScheduler` 并发池），store 只需持有 `uploadFiles` 列表并在 UI 引用。XHR、`FormData`、`Blob` 在 RN 均为全局可用，无需额外 polyfill 导入。

## 4.3 上传逻辑移植（`transferManager2.ts`）

FFBox 核心流程（`addUploadTask`）：
1. 读文件大小，按 `<1GB → 4MB / ≥1GB → 20MB` 分片。
2. **读取**：逐片读入内存（`SingleTaskScheduler` 并发 1）。
3. **哈希**：并行算每片 SHA1（并发 ≈ CPU 数），得到 `chunk.hash`。
4. **缓存检查**：`POST /api/v1/upload/check/`，传 `[fileBaseName⬝SHA1(拼接hash)]` 或各片 hash，返回已缓存列表。
5. **上传**：未缓存分片并发上传（`POST /api/v1/upload/file/`，multipart，字段 `name`=hash、文件 `file`=内容）。
6. **合并**：全部完成后 `mergeUploaded(taskId, hashs, fileBaseName, inputName, fileTime)`。
7. 更新 `setUploadStatus(taskId, isUploading)`。

RN 侧对应改动：
- 分片读取：`readAsStringAsync(fileUri, { encoding: 'base64', position: offset, length })`（`expo-file-system/legacy`，替代 `nodeBridge.getLocalFileChunk`）。
- 哈希：原生哈希（`expo-crypto.digestStringAsync`，对 base64 串算 SHA1）（替代 Web Worker）。
- 上传：XHR + `xhr.upload.onprogress` **原样保留**（RN XHR 支持上传进度，无需换库）。
- 并发池：`SingleTaskScheduler` 逻辑可原样保留（纯 JS，无平台依赖）。

```ts
// src/logic/transferManager.ts（骨架）
export async function addUploadTask(server, fileUri, taskId, fileBaseName, inputName) {
  const info = await getInfoAsync(fileUri);
  const fileSize = info.exists ? info.size : 0;
  const segment = fileSize < 1e9 ? 4e6 : 20e6;
  const file: UploadFile = { taskId, fileBaseName, chunks: [], size: fileSize, status: 'waiting' };
  // ... 异步执行读取/哈希/上传/合并（同 FFBox），平台差异点如上
  return file;
}
```

## 4.4 添加任务动作（`appStore`）

参考 `appStore.addTasks`（multiTask 分支），FN 端简化（单文件/多文件都可）：

```ts
async addTasks(fileUris: string[], names: string[]) {
  const server = this.currentServer; if (!server) return;
  const entity = server.entity;
  // 1. 需要上传 → 用占位名创建任务
  const inputNames = names.map(n => `[uploading] ${n}`);
  // 注：移动端无 globalParams（已注释）。此处参数用「选中预设的 params」或默认预设，
  //    具体回到步骤 5 参数编辑恢复点（fetchAVOptions/checkAndApplyCodecDefaults）后再确定。
  const ids = await entity.taskAddBatch(inputNames, defaultParams);
  // 2. 对每个文件启动上传
  for (let i = 0; i < ids.length; i++) {
    const file = await addUploadTask(server, fileUris[i], ids[i], names[i], inputNames[i]);
    server.data.uploadFiles.push(file);
  }
  // 3. 选中新任务并跳转选择预设
  this.selectedTask = new Set(ids);
  return ids;
}
```

> **权限判断**：FFBox 依据 `permissions.includes(Permission.FileSystem)` 决定是否需上传。移动端连接的是远程服务器，通常无该权限 → 走上传路径。若服务器开放了 FileSystem 权限，则直接传真实路径（但移动端拿不到绝对路径，一般仍需上传）。

```ts
// 选中预设后
async applyPresetToTask(taskId: number, params: OutputParams) {
  const server = this.currentServer!;
  const task = this.getTaskById(taskId)!;
  const latestRun = task.runs[task.runs.length - 1];
  const isRunning = [TaskStatus.running, TaskStatus.paused, TaskStatus.stopping, TaskStatus.finishing].includes(task.status);
  if (isRunning) return; // 不允许
  const hasFinished = [TaskStatus.finished, TaskStatus.error].includes(task.status);
  if (hasFinished) {
    const newRun = getNewUIRun(JSON.parse(JSON.stringify(latestRun.after)));
    task.runs.push(newRun);
    task.status = TaskStatus.idle;
  }
  // 本地替换 + 后端 setParameters
  latestRun.after = replaceOutputParams(params, latestRun.after, true);
  server.entity.setParameters([taskId], params, true);
}
```
